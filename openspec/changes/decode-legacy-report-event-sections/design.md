# Design

Native CF/XML independently establishes owner class 53/58 and the already supported strict owner identity 1/9. The section collection is 932159f9-95b2-4e76-a8dd-8849fe5c5ded; each row has three items and tag 1 at row[1]. The wrapper is 1/3, body 11/9 with four generated GUIDs, identity wrapper 0/2 and existing strict identity 1/7. Fields use collection 888744e1-b616-11d4-9436-004095e12fc7, row 2, wrapper 6/4, body 27/23, typed 2/3 and identity 1/7. Comments are empty and identity flags zero. The catalog section wrapper has a trailing atom 0; field-wrapper trailing atoms are measured as 0/1 for strings and 1/1 for Boolean. Accept only those measured binary first flags with fixed final 1; do not infer their semantics.

Parameterize the existing fully staged legacy document-section helper with an explicit document/catalog profile selecting collection, wrapper shape and field profile. Preserve the document profile exactly. Reuse staged typed-row parsing instead of duplicating a parser. Catalog sections are projected after its independently complete own attributes, with owner and own identities reserved; stage every section and field before publication. Unknown shapes, counts, headers, declarations, missing/duplicate descriptors or identities and cross-collection collisions produce no section prefix and preserve exact own declarations.

The reached native catalog has one section and four fields (three unlimited Variable strings and Boolean). Preserve all UUIDs/names/order/types/qualifiers against XML. The earlier measured report-deliveries catalog has the same profile with two strings, serving as a second retained native pair. No new API, shared header expansion, modern path rewrite, catalog settings or runtime write support is required.
