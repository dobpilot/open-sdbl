# Design

Reuse the existing GUID and Synonym types. Read-only demo acquisition proves that copied processes can retain the same point GUID. Therefore point identity is composite (owner GUID, point GUID), unlike globally indexed ConfigDescriptor identity. Use nested BusinessProcessRoutePoint values without polluting the global descriptor index. Publish membership only when the entire measured collection is structurally valid and each member retains its native identity and name. Distinguish `Some([])` from unknown `None`. Keep the generated route-point reference type separate from owner/member identities. Preserve acquired ordering without promising BSL iteration order.

Native evidence must be obtained using a throwaway configuration, then compared against XML actually dumped by 1C; input XML alone is not evidence. Original databases are read-only. Exact resource positions are recorded only after measurement.

Measured resource: the native `.7` graph version 5 carries an exact item count, paired item kind/body entries and final item counter. Native XML from the same saved Designer configuration verifies all ten point members across the nine named point kinds; lines and decorations are excluded. The empty older native control has count zero. The BP header retains route-reference TypeId at position 13 in the measured class 30 form. Unsupported collection count, item kind/header/identity, duplicated member IDs or names makes the entire graph unknown. Native read-only demo showed repeated point GUIDs across processes, motivating owner-qualified nested values rather than globally indexed descriptors.
