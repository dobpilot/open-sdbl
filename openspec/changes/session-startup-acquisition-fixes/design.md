## Decisions
One owned connection carries an explicit, non-nested READ COMMITTED transaction. Begin while active and finish while inactive return errors. State is checked against the server, and dead/closed sessions never report active. Queries reuse explicit transactions and preserve automatic transactions otherwise. Query/callback/timeout errors roll back, or disconnect when cleanup is unsafe. External future cancellation marks operation state uncertain; the next operation rejects reuse and disconnects. Metadata/configuration acquisition rejects explicit transactions without touching their state. PostgreSQL enforces READ ONLY; SQL Server retains its existing transport read-only intent and requires a read-only login for actual server write denial. Close and Drop disconnect the connection, causing server rollback. Blocking methods delegate through the owned runtime and preserve AsyncContext/SessionClosed.

Functional-option Content accepts only the measured counted wrapper and reference grammar, using the existing owner-reference parser. Location and flag are published only after validating the full class, Content and independent fields. Native false/true XML/CF and retained UNF bytes are regression evidence.
