# Design

Base05a24e5. Proposed additive field `CompiledQuery.logical_projection: Option<Vec<LogicalResultColumn>>` (one surface, no duplicate getter). Ordered position is logical occurrence. `LogicalResultColumn { name: String, value: LogicalResultValue }`; enum Scalar { column: usize }, Composite { discriminator: usize, members: Vec<CompositeResultMember> }; member { type_tag: u8, column: Option<usize> }. None member column is reserved for exactly known valueless Null/Undefined alternatives; payload variants reference final `CompiledQuery.columns` and use its existing ColumnKind. Non-exhaustive public structures/enums, Russian rustdoc.

Capture names/occurrences before compile_selected_projections flattens composite Scalar/CASE; keep existing logical_columns width bookkeeping and SQL behavior untouched. Carry separate roles through member generation, rendered projections, CompiledBranch and final CompiledQuery. Source-free compilation needs the same capture. Preserve first branch occurrence/name through UNION normalization and reference widening. Derived compilation must carry semantic roles from projected fields, not recover them by physical labels/origin. Existing projected RTRef/RRRef collapse remains one reference cell.

Record type roles where existing resolved storage metadata and composite_member_of know them. Do not reverse-engineer output label suffixes for the new API. B|S tags are Boolean2/String5; reference tags preserve existing TypeValue protocol. Binary/Uuid both map to Null tags in current expression generation, so shapes with indistinguishable active payloads must be unavailable. Do not broaden compiler acceptance. Validate final indices, coverage and exclusion of service columns before publishing any complete recipe. Nested/totals/deferred contexts initially unavailable unless exact coverage can be carried without broader object models.

No code has been changed at this design stage. First native own B|S control will test one logical column and correct Boolean/String active values; it does not by itself validate physical SDK discriminator indices. SQL corpus, all old expectations, aliases/CASE/UNION/reference/derived boundary tests and full SDK gates are required before implementation commit. Release number remains unassigned.

Implementation boundary: source-free CASE with differing kinds remains its existing compiler rejection. Derived sources, nested results, totals and deferred transformations return None in this first draft. Untagged SQLNULL coercion cannot preserve Undefined versus Null; explicit Undefined coercion through CASE/UNION is therefore unavailable. Composite storage fields include existing measured Undefined tag1 with columnNone; query Null does not imply fieldtag0. The final physical discriminator index is recorded from resolved storage member metadata during generation, never recovered from emitted SQL labels.

Native own positive control completed in tests/fixtures/logical-query-projection-native-1013. New empty-context attempts produced internal platform errors without a completed oracle; no semantic conclusion or causal explanation is drawn from them. Reusing the existing own privileged-query manager context produced completed Boolean/String, CASE, Null/String and Undefined/String output with one logical column.

Specialized presentation lookup and placement-count helpers also expose no recipe in this first scope; ordinary SELECT COUNT remains a supported scalar. The raw discriminator tag protocol is reused from TypeValue, with no guessed fallback or new value codec.
