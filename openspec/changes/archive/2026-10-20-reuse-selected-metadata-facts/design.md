# Design
ConfigurationMetadataCache::new(Limits), admit(&ConfigResource), and resolve(&ConfigurationMetadataInputs, Vec<ExtensionMetadata>) are the complete API. Each successful admission decodes once; duplicate filenames are rejected before decoding, since replacing an immutable admitted resource is not supported. Failed admission leaves accumulated facts and budgets unchanged. The cache retains parsed facts and filenames, not compressed buffers or an extra compressed collection. Resource count/compressed bytes follow Limits and decoded resource/total budgets use the existing decoder defaults.

The old stateless resolver retains its current input/limit behavior. Both paths share aggregation, route-point finalization, strict separator/dependency validation, unsupported-loaded-descriptor rejection, and snapshot construction. Resolve clones parsed facts because returned immutable snapshots own them; it never decodes old bytes. Stable ordering and existing fingerprints remain authoritative.

Schema lookup indexes use exactly folded_name, which is the existing names_equal hash key. Service mapping chooses the earliest source-schema row among alias, numbered and extra-dimension candidates, preserving OR/first-match precedence. Dependency ownership indexes preserve the original first nonservice owner; other existing last-wins maps are not silently reused. The original scan is kept only as a test oracle. No language/storage/isolation semantics change and no A/B performance claim is made from the diagnostic CPU sample.
