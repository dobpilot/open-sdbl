# Design

The selector receives `root` first and returns the name of the configuration descriptor. It receives that descriptor next, then decides which additional Config resources to retain. The two bootstrap resources are retained unconditionally. Providers point-read them through the same transaction, then stream the remaining Config rows. A resource is decoded for metadata whether or not retained; unselected compressed bytes are dropped as soon as decoded. Existing resource and byte limits apply to retained Config and independently to ConfigCAS. The entire ConfigCAS store is still required to group extensions and resolve their metadata; this change does not claim to eliminate its peak. No SQL is added to the blocking driver.

The selected read is distinct from the whole read to keep that API's complete-resource contract intact. The PostgreSQL and SQL Server adapters share the same selector and acquisition pipeline. A missing bootstrap resource, invalid descriptor name, or selector error aborts acquisition through the existing rollback path. The remaining-resource query excludes both bootstrap names, so each resource is transferred once within the selected acquisition.

`ensure_users` and `ensure_rights` on the blocking session drive the existing asynchronous functions through the same runtime and connection. The caller owns `AccessStore`, allowing user/role caching for the session. Closed-session and async-context precedence follows the other blocking methods. The unknown extension safe-mode flag and incomplete extension object catalogs are outside this change.
