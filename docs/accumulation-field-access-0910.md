# Права полей регистров накопления в 0.9.10

Нативные квитанции и XML ролей сохранены в `tests/fixtures/access/native-0910` вместе с исходным provenance и хешами. Завершённые измерения 1С 8.3.27.2342 подтверждают чтение собственных измерений и ресурсов через Read регистра независимо от View и default-флагов. Read=false отвергает в том числе РАЗРЕШЕННЫЕ.

Публичные сигнатуры не меняются: адаптер продолжает использовать `check_user_field_access` и `user_decisions`. Нативный Config должен доказывать полные коллекции, вид регистра Balance и тип поля; неизвестные поля, роли и пользователь не разрешаются. RLS по-прежнему компилируется существующим путём, несколько ограниченных ролей объединяются через ИЛИ.

## Ограничение обычного запроса при RLS

Существующий компилятор формирует отфильтрованный SQL через AccessDecision/RestrictionMode. Он не предоставляет отдельного плана проверки запрещённых прочитанных строк и не воспроизводит нативную ошибку обычного запроса при обращении к ним. Поэтому результат field authorization и успешная компиляция SQL не доказывают полную семантику ordinary RLS. Нельзя автоматически заменять обычный запрос на РАЗРЕШЕННЫЕ или трактовать пустую выборку как отсутствие запрещённых строк. Требуется отдельное проектирование исполнения/проверки в компиляторе; это не входит в узкую поправку сопоставления полей 0.9.10. Измерение менеджера — доказательство для потребителя, не новый метод SDK.

Тайм-аутные журналы отказа менеджера не являются завершёнными квитанциями. Ошибка Количество() коллекции ролей не означает количество ролей; наличие обеих ролей проверено РольДоступна.

Оборотные регистры не получили независимого контроля прав и не разрешаются новым правилом; отсутствующие и пустые объявления типов также не дают положительного доказательства.

## Граница регрессионных тестов

Новый integration test декодирует нативный Config регистра из `runtime-object-099`. Физическая схема создана для проверки разрешения полей, а структуры RoleRights собраны из прежних бинарных фикстур с заменой GUID/Read/RLS на измеренные контрольные значения. Это проверка policy API, а не SQL-исполнение на живом сервере и не round-trip бинарных ресурсов новых контрольных ролей: для них сохранены нативные XML и квитанции, но не `.0` Config. Старые тесты не изменялись.
