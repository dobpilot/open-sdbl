# Условное разделение 0.9.14

`DataSeparationSettings::conditional_separation` и разрешённый `DataSeparation::conditional_separation` сохраняют GUID константы. `SessionParameters::set_separation_condition(Guid, bool)` передаёт её текущее значение отдельно от именованных параметров. Getter `separation_condition(&Guid)` и удаление `remove_separation_condition(&Guid)` позволяют хосту обновлять это значение; SDK не делает I/O и не кеширует его между компиляциями.

При отсутствии необходимого значения `QueryDiagnostic::missing_separation_condition()` возвращает `Some(&Guid)`. Категория — Metadata; `missing_parameter_name()` — None, `is_missing_session_parameter()` — false. Например, demo сообщает GUID `cc906f05-5ea6-43cb-a084-c4ee51ca4bd5`. Хост читает эту константу своим Session-owned соединением, передаёт boolean и повторяет компиляцию. Права, RLS и разрешения на чтение константы остаются обязанностью существующего адаптера.

False-condition допускает только измеренные String/Number пустые области (пустая строка/0) в Independent и Shared. Use/value в этом случае не требуются. True-condition сохраняет 0.9.13: Independent false-use запрещает чтение, Shared false-use допускает все области. Старый отдельный отказ `ИЗ Константы` без единственной области остаётся. L/T/R и другие conditional-empty формы явно отклоняются; для именованного реквизита неразобранные настройки также дают явный отказ, а не притворяются nil-условием. Подготовка и источники без соответствующего столбца условия не требуют.

Нативные артефакты 8.3.27.2342 удержаны в `tests/fixtures/conditional-separation-0914/`: собственные CF/XML пары для заданного и отсутствующего условия, ресурс common attribute, четыре receipts S/N Independent/Shared и исходные скрипты. Третья ссылка собственного Config равна GUID булевой константы в XML; nil-форма подтверждена отдельной повторной выгрузкой. demo target дополнительно проверен приобретённым каталогом: имя `ИспользоватьРазделениеПоОбластямДанных`, Constant, `_Const1835`, тип B.

Правки прежних тестов ограничены входами: `query_accounting`, `query_corpus`, `query_parameter_tables`, `query_system_values`, `query_tuple_in`, `query_compile`, `query_registers`, `query_refs`, `query_dereference`, `query_strict_restrictions` явно передают true-условия уже включённого разделения через общий helper. Это воспроизводит прежний активный сценарий после исправления потерянной третьей ссылки. `query_separators` дополнен двумя обязательными `conditional_separation: None` для существующих nil-форм. SQL snapshots, ожидаемые SQL и диагностические assertions не изменены и не ослаблены. Два ожидаемых Rust-литерала DataSeparationSettings получили обязательное поле None, без изменения прежних значений. Новый отдельный набор проверяет false/true/missing, замену значения, типы, оба SQL backend, прямые источники/константы/разыменования/виртуальные таблицы и неподдержанные настройки.
