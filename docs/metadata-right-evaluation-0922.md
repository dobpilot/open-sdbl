# Права метаданных в 0.9.22

Чистый `open_sdbl::metadata::resolve_metadata_right(snapshot, owner, right_name, standard_attribute)` проверяет структуру до обхода разрешений привилегированным режимом. `ResolvedMetadataRight::applicability()` возвращает `Applicable` либо `NotApplicable`, `right()` — известное каноническое право. Неизвестные имена, отсутствующий владелец, пустой/неизвестный путь и неподдержанная форма возвращают `MetadataRightError`; это не отказ роли.

Поддержаны справочники: `Read`/`View` владельца и `Code`/`Код`, `Description`/`Наименование` с приобретёнными положительными длинами. Русские и английские имена регистронезависимы. `Read` действительного стандартного реквизита неприменимо: хост самостоятельно возвращает успех для VerifyAccessRights либо ошибку применимости для AccessRight. SDK не знает BSL-исключений, кадров, журнала и привилегий.

Для применимого права `AccessStore::metadata_right(roles, target)` вычисляет AccessRight по полному кешу ролей; `metadata_right_for_verification(roles, target)` — измеренный вариант VerifyAccessRights. Чистые аналоги одной роли — `target.granted_by(role)` и `granted_for_verification(role)`. Оба кешированных метода проверяют полноту всех переданных ролей до вычисления. Используйте права того же приобретённого снимка, по которому разрешена цель. Новый запрос или соединение не создаются.

Существенное нативное различие: independent=true, defaults=false, owner View=false, явный Code View=true дают AccessRight=false, но VerifyAccessRights проходит. Оно обнаружено replay исходных артефактов; первоначальный запрос ошибочно распространял parent gating на оба оператора. В остальных сохранённых профилях родитель и реквизит проверяются внутри одной роли до OR результатов ролей. Неизмеренное сочетание independent=true/defaults=true без parent grant явно отклоняется.

Фикстуры `tests/fixtures/metadata-right-native-0922` сохраняют 492 исходных результата 1С 8.3.27.2342 и нативные CF/сжатые права. SQL/RLS авторизация не изменена: проверка прав метаданных не даёт разрешения SQL-чтения и не заменяет `check_user_field_access` или решения RLS. Другие виды/права и нулевые/неизвестные стандартные длины не заявлены совместимыми.
