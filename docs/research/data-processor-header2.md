# Собственные реквизиты обработки со старым заголовком

Исходный BUH owner 4507a92e-abb6-4329-88b2-3429bc694bc6 содержал три корректных реквизита, однако SDK выдавал неизвестное членство. Существующий owner class 17/12 проходил проверку; отказ происходил в двух местах: декодирование типов `attribute_bodies` и членство `complete_attributes` использовали общий `header`, принимающий только version 3.

Независимый контроль платформы 8.3.27.2342 загрузил собственный CF с неизменённым original owner и полным объявленным набором его четырёх детей в новую файловую базу, затем штатно выгрузил XML. Подтверждены порядок, имена, GUID и типы трёх реквизитов, отсутствие частей, две формы и два макета. Контейнер собирался только существующим v8unpack; байты всех 11 импортированных ресурсов совпали после повторного извлечения. Согласованы собственный Config-каталог и versions-индекс; исходные BUH/demo/UNF не менялись. Полный протокол сохранён в `/tmp/sdbl-buh-attribute-header2-transplant-1013`, переносимый минимальный корпус — `tests/fixtures/data-processor-header2`.

Первые два реквизита — String Length 0/150 Variable. Третий native XML TypeSet — `cfg:ExchangePlanRef`: исходный Pattern #0a52f9de-73ea-4507-81e8-66217bead73a сохраняется без выдуманного конкретного объекта. Внешние placeholders не понадобились. Прикладные BSL-модули не выполнялись.

Исправление оставляет общий `header` и пути Report/частей прежними. Только после существующих guards обработки отдельный fallback проверяет заголовок владельца 2/8, собственную коллекцию ec6bb..., обёртку 0/2, тело 27/23, типизированную обёртку 2/3 и заголовок идентичности 2/8 с измеренными полями. Он проверяет уникальность GUID, наличие единственного дескриптора и непустую корректную декларацию каждого члена до изменения типов и публикации полного списка. Другие формы остаются неизвестными; API и версия не менялись.

Exact original regression до исправления падал на None членства. Нативный оракул, red-квитанция и SHA256 включены в корпус. Отрицательные проверки охватывают nil/повторные GUID, неверную self-reference, длины и коды тела/заголовка, неизвестную декларацию, повреждённый count и другие owner-контексты. Существующие ожидания тестов не менялись.

CompatibilityMode 8_2_16 собственного современного контроля оставил header 3; он не является основанием этой правки. Предыдущий transplant без объявленных детей получил общее нарушение целостности; единственная причина отказа не устанавливалась.

Проверки: fmt, Clippy всех целей с запретом предупреждений, rustdoc всех пакетов с запретом предупреждений и strict OpenSpec прошли. Все тесты workspace завершены: 939 passed, 13 ignored, включая четыре новых проверки. Первый sandbox-запуск прошёл core и CLI, но восемь DB-тестов loopback bind получили PermissionDenied; оставшиеся workspace-пакеты повторены с разрешённым loopback, затем проверены core doctests и окончательные новые guards. Никакие ожидания существующих тестов не менялись. Квитанции: `/tmp/sdbl-buh-attribute-header2-transplant-1013/sdk-gates`.
