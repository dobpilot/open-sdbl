# Измеренная роль расширения без подобъекта прав

BUH останавливалась на полноте прав `ДемоПроф_ОбщиеПрава`, UUID
`2bc105dd-b388-436d-9410-a756e3415d30`. Расширение и его root доступны;
fallback не терял ресурс. Текущий индекс содержит дескриптор, но не `.0`.
Read-only проверка основного Config также не нашла `.0` или одноимённой
основной роли. Нативный перенос точных исходных байтов в собственный CF
подтвердил допустимость роли без Rights.xml; отдельные выбранные
пользователи подтвердили доступность роли без дополнительных проверенных
прав. Явно пустые права имеют другой descriptor-признак и отдельный `.0`.

Из-за нового поддержанного представления до кода создан и строго проверен
OpenSpec change `decode-empty-extension-role-rights`. Он остаётся активным:
версия 0.9.15 и публичные API не изменены, релиз и архивирование не выполнялись.

Изменение ограничено fallback в `open-sdbl-db::extensions`. Полная измеренная
форма с совпадающим собственным UUID и признаком отсутствия подобъекта прав
даёт пустые RoleRights только при необъявленном `.0`. Для создания значения
использован существующий декодер и 31 неизменённый байт отдельно измеренного
пустого ресурса; новый конструктор и новый публичный API не нужны. Все
неизвестные или недоступные формы остаются unreadable. Объявленный `.0`
всегда имеет приоритет и разбирается прежним путём.

Фикстуры и границы измерения:
[empty-role-native](../../tests/fixtures/extension/empty-role-native/README.md).
Нативный XML собственной основной конфигурации не является измерением
ObjectBelonging исходного расширения; связь с основной ролью не выдумывается.

Проверки: 3 новых unit-теста с exact native fixture и отрицательными
мутациями; публичный fallback red/green на отдельной собственной PostgreSQL
базе; 11 сценариев недоступных/повреждённых дескрипторов и приоритета `.0`.
Старые ожидания тестов не изменены. `cargo fmt --all -- --check`,
`cargo clippy --offline --workspace --all-targets -- -D warnings`,
`cargo test --offline --workspace`,
`RUSTDOCFLAGS="-D warnings" cargo doc --offline --workspace --no-deps` и
`openspec validate --all --strict` завершились успешно. Кластер PG55439
после контрольных сценариев остановлен; исходные базы и права не изменялись.
