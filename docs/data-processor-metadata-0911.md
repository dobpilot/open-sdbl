# Метаданные собственного объекта обработки, SDK 0.9.11

`ConfigDescriptor` предоставляет `data_processor_attributes`,
`data_processor_tabular_sections` и `data_processor_object_type`.
Первые два поля — приобретённые полные упорядоченные списки GUID,
`None` означает неизвестную/неполную форму, `Some([])` — проверенную пустоту.
Поля табличной части остаются в существующем `tabular_section_attributes`
описателя части. Object GUID отделён от Manager и не подменяет ссылочный тип.

Декодер узнаёт измеренную форму класса 17 и переиспользует общие описатели,
типы, квалификаторы, синонимы и настройки заполнения. Ни исходники BSL,
ни имена ресурсов не используются для угадывания состава. Другие классы
получают `None`. При выборочном чтении описатели сохраняются, даже если
байты всех исходных ресурсов объекта отброшены.

Парный нативный контроль находится в `tests/fixtures/data-processor-0911`:
штатный CF, обратная XML-выгрузка, бинарные ресурсы, независимая карта GUID
и хеши. Он содержит переставленные реквизиты, две непустые и одну пустую
часть, отдельную пустую обработку. Проверки повреждений синтетические и
не выдаются за платформенные измерения. Платформа Linux 8.3.27.2342;
Windows и живой SQL Server отдельно не проверялись. Новых зависимостей нет.

Итоговый полный `cargo test --workspace --locked`: 871 passed, 0 failed, 13 ignored. Formatting, workspace all-targets Clippy с `-D warnings`, rustdoc с `-D warnings` и строгая проверка OpenSpec прошли. В существующих тестах механически дополнены только пять литералов `ConfigDescriptor` в четырёх файлах обязательными полями `None`; прежние ожидания поведения не менялись.
