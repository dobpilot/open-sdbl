# Язык запросов 1С: статус поддержки в open-sdbl

Сверка выполнена 2026-09-10 по версии 0.3.3. Перечень возможностей
языка запросов взят из Синтакс-помощника платформы 8.3.27.2342 (раздел
«Язык запросов», через MCP-сервер unica, корпус `platform-help`); в графе
«Справка» указан `documentId` страницы, по которой проверена конструкция.
Статус — из кода `open-sdbl` (`src/lexer.rs`, `src/query/core/parser.rs`,
`src/query/core/codegen/`) и спецификаций `openspec/specs/`.

Обозначения: ✅ поддерживается · 🟡 частично (см. примечание) · ❌ не
поддерживается. В графе «Примечание / реакция» — диагностика, которую
выдаёт компилятор (`QueryDiagnosticKind`), если конструкция встречается в
запросе.

Сокращения `documentId`: префикс `G:` = `platform-syntax-help:platform-guides:`,
префикс `T:` = `platform-syntax-help:syntax-context:tables/`.

## 1. Структура запроса

Порядок предложений по справке (`G:SELECTSection`): `ВЫБРАТЬ [РАЗРЕШЕННЫЕ]
[РАЗЛИЧНЫЕ] [ПЕРВЫЕ n] <поля> [ПОМЕСТИТЬ …] [ИЗ …] [ИНДЕКСИРОВАТЬ ПО …]
[ГДЕ …] [СГРУППИРОВАТЬ ПО …] [ИМЕЮЩИЕ …] [ДЛЯ ИЗМЕНЕНИЯ …]`, затем
`ОБЪЕДИНИТЬ`, `УПОРЯДОЧИТЬ ПО`, `АВТОУПОРЯДОЧИВАНИЕ`, `ИТОГИ`.

| Конструкция (RU / EN) | Статус | Примечание / реакция | Справка |
|---|---|---|---|
| `ВЫБРАТЬ` / `SELECT` | ✅ | | `G:SELECTSection` |
| `РАЗЛИЧНЫЕ` / `DISTINCT` | ✅ | | `G:SELECTSection` |
| `ПЕРВЫЕ n` / `TOP n` | ✅ | `TOP (n)` на MSSQL, `LIMIT n` на PostgreSQL; `n` — целое > 0 | `G:SELECTSection` |
| `РАЗРЕШЕННЫЕ` / `ALLOWED` | ❌ | не ключевое слово → `Syntax`; RLS-ограничения в SQL не воспроизводятся | `G:SELECTSection` |
| Псевдонимы `[КАК]` / `[AS]` | ✅ | для полей и источников; `КАК` необязательно и в 1С | `G:SelectionFieldsList` |
| `*` | 🟡 | только без других полей и без `JOIN` | `G:SelectionFieldsList` |
| Запрос без `ИЗ` | ✅ | в 1С `ИЗ` можно опустить при полностью квалифицированных полях; open-sdbl без `ИЗ` компилирует только выражения без источника (`ВЫБРАТЬ 1`) | `G:FromStatement` |
| Вложенные таблицы в выборке `Состав.(Поле, …)`, `Состав.*`, `ПУСТАЯТАБЛИЦА.(…)` / `EMPTYTABLE` | ❌ | табличная часть доступна только как отдельный источник `Документ.X.Состав` | `G:SelectionFieldsList` |
| `ПОМЕСТИТЬ <ВТ>` / `INTO`, `УНИЧТОЖИТЬ <ВТ>` / `DROP` | ✅ | базы-копии только на чтение, поэтому таблица эмулируется CTE `vt1`, `vt2`, …: `ПОМЕСТИТЬ` определяет CTE и возвращает строку `Количество`, `УНИЧТОЖИТЬ` SQL не порождает и скрывает имя (можно определить заново); определения хранит `TempTablesManager`, в `WITH` попадают только достижимые; правила определения — как у вложенного запроса (`*`, отложенные представления и `УПОРЯДОЧИТЬ ПО` без `ПЕРВЫЕ` запрещены); неизвестное или дублирующее имя — `TemporaryTable` | `G:INTO`, `G:Work with temp table` |
| `ДОБАВИТЬ <ВТ>` / `ADD` (добавление строк в существующую ВТ) | ✅ | новая CTE `SELECT … FROM vtK UNION ALL <оператор>`, имя переключается на неё; структура сверяется строго (число колонок, виды, цели и ширина ссылок), расширения типа нет; метки колонок остаются от первого определения; поле перед `ДОБАВИТЬ` не обязано иметь псевдоним, в отличие от 1С | `G:temp_ADD` |
| `ИНДЕКСИРОВАТЬ ПО …` / `INDEX BY`, `ИНДЕКСИРОВАТЬ ПО НАБОРАМ ((…),(…))` / `INDEX BY SETS`, модификатор `УНИКАЛЬНО` / `UNIQUE` | 🟡 | разбирается и проверяется (поля обязаны быть в списке выборки, иначе `TemporaryTable`), SQL не порождает: у CTE индексов нет | `G:INDEXBY` |
| `ИЗ <ВТ> [КАК Псевдоним]` (чтение временной таблицы) | ✅ | имя без точки читается как временная таблица, в том числе в соединениях, вложенных запросах и `В (…)`; без псевдонима квалификатором служит имя таблицы; колонки приходят с видами из определения; разыменование — как у вложенного источника | `G:Work with temp table` |
| `ИЗ &ВнешнийИсточник` (ВТ из таблицы значений) | ❌ | внешние источники данных в компиляторе отсутствуют | `G:INTO` |
| `ИЗ` / `FROM`: несколько источников через запятую | ❌ | декартово произведение через запятую не поддерживается; используйте соединения | `G:FromStatement`, `G:JOIN` |
| `ИЗ (вложенный запрос) КАК Псевдоним`, в том числе в соединениях | ✅ | псевдоним обязателен; колонки подзапроса становятся полями источника с их `ColumnKind`; внутри допустимы объединения, группировка, соединения, `ПЕРВЫЕ`, `РАЗЛИЧНЫЕ`, inline-представления, `УПОРЯДОЧИТЬ ПО` только вместе с `ПЕРВЫЕ`; запрещены `*` и отложенные представления; разыменование — только через колонку-ссылку с одной фиксированной целью; коррелированные ссылки на внешние источники — диагностика; глубина вложенности ≤ 16 | `G:FromStatement` |
| `[ВНУТРЕННЕЕ] СОЕДИНЕНИЕ`, `ЛЕВОЕ/ПРАВОЕ/ПОЛНОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ … ПО` / `[INNER] JOIN`, `LEFT/RIGHT/FULL [OUTER] JOIN … ON` | 🟡 | цепочка любого числа соединений в порядке записи; `ПО` каждого соединения содержит хотя бы одно равенство прямых полей присоединяемого и любого более раннего источника, дополнительно — скалярные фильтры через `И`; ссылка на источник, присоединяемый позже, — диагностика; `ПОЛНОЕ` допустимо только единственным соединением ветви, транспонируется в `UNION ALL`, агрегаты над ним запрещены | `G:INNERJOIN`, `G:LEFTJOIN`, `G:RIGHTJOIN`, `G:FULLJOIN` |
| `ГДЕ` / `WHERE` | ✅ | | `G:WhereStatement` |
| `СГРУППИРОВАТЬ ПО` / `GROUP BY`, `ИМЕЮЩИЕ` / `HAVING` | ✅ | ключи — путь поля (одно разыменование), псевдоним проекции или выражение, совпадающее с проекцией; каждая неагрегатная проекция обязана быть ключом; ссылочный ключ группируется по всем физическим членам; `ИМЕЮЩИЕ` — предикат с агрегатами; сортировка сгруппированной ветви — только по ключам и псевдонимам; с `ПОЛНОЕ СОЕДИНЕНИЕ` — диагностика | `G:GROUPStatement`, `G:aggregate_function_values_restrictions.html` |
| `СГРУППИРОВАТЬ [ВСЕ] ПО ГРУППИРУЮЩИМ НАБОРАМ ((…),(…))` / `GROUP BY GROUPING SETS` | ❌ | | `G:GROUPStatement` |
| `ОБЪЕДИНИТЬ [ВСЕ]` / `UNION [ALL]` | ✅ | ветви должны совпадать по числу колонок и вариантам `ColumnKind` (`NULL` совместим с любым); 1С в этом месте образует составной тип | `G:UNIONSection` |
| `УПОРЯДОЧИТЬ ПО … ВОЗР/УБЫВ` / `ORDER BY … ASC/DESC` | 🟡 | только в конце запроса, только по полям (без выражений и порядковых номеров); при `JOIN`/`UNION` поле должно быть в проекции | `G:SELECTSection` |
| `УПОРЯДОЧИТЬ ПО … [ВОЗР/УБЫВ] ИЕРАРХИЯ` / `HIERARCHY` | ❌ | | `G:hierarchical_ordering.html` |
| `АВТОУПОРЯДОЧИВАНИЕ` / `AUTOORDER` | ❌ | | `G:AUTOORDER` |
| `ИТОГИ [поля] ПО [ОБЩИЕ] точки [[ТОЛЬКО] ИЕРАРХИЯ] [ПЕРИОДАМИ(…)]` / `TOTALS … BY [OVERALL] … [[ONLY] HIERARCHY] [PERIODS]` | ❌ | итоговые строки — особенность результата запроса 1С, в SQL не отображаются | `G:query_totals.html`, `G:hierarchical_totals.html` |
| `ДЛЯ ИЗМЕНЕНИЯ [OF таблицы]` / `FOR UPDATE [OF]` | ❌ | компилятор только для чтения | `G:SELECTSection` |
| `[НЕ] В (вложенный запрос)` | ✅ | подзапрос ровно с одной колонкой совместимого вида; ссылки сравниваются на одной ширине (fixed сторона расширяется до `RTRef ‖ RRRef`); подзапросы в списке выбора — ❌ (их нет и в 1С) | `G:condition_expressions.html` |
| Пакет запросов `;` | 🟡 | операторы пакета компилируются последовательно (не более 64) и собираются в один SQL-оператор: результат даёт последний, как `Запрос.Выполнить()`; промежуточные запросы без `ПОМЕСТИТЬ` только проверяются; массива результатов, как у `ВыполнитьПакет()`, нет; пакет из одного `УНИЧТОЖИТЬ` строк не возвращает | `G:WorkinWithBath` |
| Разыменование `Поле.Реквизит[.Реквизит…]` | 🟡 | один шаг; глубже — «reference paths deeper than one hop are not supported»; в `ПО` разыменование запрещено; имя таблицы можно опускать, если поле уникально среди источников | `G:field_dereferencing.html` |
| `.Представление` / `.Presentation` | ✅ | через callback-план приложения (см. README «Callback ABI представлений») | — |

## 2. Операторы

Грамматика логических выражений по справке (`G:condition_expressions.html`,
`G:OperationLogCompare`): сравнение `> < = >= <= <>`, `[НЕ] В [ИЕРАРХИИ]
(список | подзапрос)`, `[НЕ] МЕЖДУ … И …`, `ЕСТЬ [НЕ] NULL`, `ССЫЛКА <Имя
таблицы>`, `[НЕ] ПОДОБНО … [СПЕЦСИМВОЛ …]`, связки `И ИЛИ НЕ`.

| Оператор | Статус | Примечание / реакция | Справка |
|---|---|---|---|
| `+ - * /` | ✅ | `%` — ❌ (в справке не описан) | `G:query_expressions.html` |
| `+` как конкатенация строк | ❌ | компилируется как арифметика (`Number`); на СУБД даст ошибку типов | — |
| `= <> < > <= >=` | ✅ | | `G:OperationLogCompare` |
| `И` / `ИЛИ` / `НЕ` (`AND` / `OR` / `NOT`) | ✅ | на MSSQL булевы поля в предикатах приводятся к `= 0x01` | `G:query_conditions.html` |
| `В (список)` / `IN (...)` | ✅ | непустой список скалярных выражений, в том числе `ЗНАЧЕНИЕ(...)` | `G:condition_expressions.html` |
| `НЕ В (список)` / `NOT IN` | ✅ | | `G:condition_expressions.html` |
| `[НЕ] В ИЕРАРХИИ (…)` / `IN HIERARCHY` | ❌ | | `G:condition_expressions.html` |
| `[НЕ] МЕЖДУ … И …` / `BETWEEN` | ❌ | не ключевое слово → `Syntax` | `G:condition_expressions.html` |
| `[НЕ] ПОДОБНО … [СПЕЦСИМВОЛ …]` / `[NOT] LIKE … [ESCAPE …]` | ✅ | шаблон передаётся в `LIKE` без переписывания на обоих провайдерах (на PostgreSQL классы `[…]` обеспечивает `mchar`); операнды — строки; только в предикатах | `G:condition_expressions.html` |
| `ЕСТЬ NULL` / `ЕСТЬ НЕ NULL` (`IS [NOT] NULL`) | ✅ | | `G:condition_expressions.html` |
| `ССЫЛКА Справочник.X` / `REFS` | ❌ | частично заменяется `ВЫРАЗИТЬ(… КАК Справочник.X) ЕСТЬ НЕ NULL` | `G:condition_expressions.html` |
| `ВЫБОР КОГДА … ТОГДА … [ИНАЧЕ …] КОНЕЦ` / `CASE WHEN … THEN … [ELSE …] END` | ✅ | вид результата — первая не-`NULL` ветвь, остальные должны быть совместимы; ссылки на разные объекты расширяются до runtime-typed payload; агрегаты внутри `ВЫБОР` допустимы в сгруппированных ветвях и в ветвях из одних агрегатов | `G:query_select.html` |

двуязычной таблицы `G:present.html` и заголовков страниц функций.

## 6. Литералы, параметры, комментарии

По справке (`G:consts_and_parameters.html`) литералами являются `ИСТИНА`,

`НЕОПРЕДЕЛЕНО`, `NULL`.

| Элемент | Статус | Примечание |
|---|---|---|
| Строки `"…"` с удвоением `""` | ✅ | многострочные литералы с `\|` — ❌ |
| Числа | ✅ | |
| `ИСТИНА` / `ЛОЖЬ` / `NULL` (`TRUE` / `FALSE`) | ✅ | |

| Комментарии `//` | ✅ | |

## 7. Что open-sdbl добавляет сверх языка 1С

- Бинарные литералы `0x…`.
- Ключевое слово `ON` вместо `ПО` в условии соединения; короткие английские
  имена видов метаданных (`Reference`, `InfoRg`, `AccumRg`, …) и физические
  имена стандартных полей (`Folder`, `ParentID`, `RecordKind`, …).
- `ColumnKind` для каждой колонки результата и нативные типы вместо текста.
- Уровень диалекта MSSQL (`2008`/`2012`), поддержка PostgreSQL 9.0+ и баз
  платформы 8.2 без `PartNo`.
