# Язык запросов 1С: статус поддержки в open-sdbl

Сверка выполнена 2026-09-09 по коммиту `c9cd9d7`. Перечень возможностей языка
запросов взят из документации 1С и грамматики проекта 1c-syntax
(см. «Источники»); статус — из кода `open-sdbl` (`src/lexer.rs`,
`src/query/core/parser.rs`, `src/query/core/codegen/`) и спецификаций
`openspec/specs/`.

Обозначения: ✅ поддерживается · 🟡 частично (см. примечание) · ❌ не
поддерживается. В графе «Реакция» — диагностика, которую выдаёт компилятор
(`QueryDiagnosticKind`), если конструкция встречается в запросе.

## 1. Структура запроса

| Конструкция (RU / EN) | Статус | Примечание / реакция |
|---|---|---|
| `ВЫБРАТЬ` / `SELECT` | ✅ | |
| `РАЗЛИЧНЫЕ` / `DISTINCT` | ✅ | |
| `ПЕРВЫЕ n` / `TOP n` | ✅ | `TOP (n)` на MSSQL, `LIMIT n` на PostgreSQL; `n` — целое > 0 |
| `РАЗРЕШЕННЫЕ` / `ALLOWED` | ❌ | не ключевое слово → `Syntax`; RLS-ограничения в SQL не воспроизводятся |
| Псевдонимы `КАК` / `AS` | ✅ | для полей и источников; для источников допускается и без `КАК` |
| `*` | 🟡 | только без других полей и без `JOIN` |
| `ПОМЕСТИТЬ` / `INTO`, `УНИЧТОЖИТЬ` / `DROP`, `ИНДЕКСИРОВАТЬ ПО` / `INDEX BY` | ❌ | временные таблицы: `UnsupportedFeature` «unsupported query syntax» |
| `ИЗ` / `FROM` | 🟡 | ровно один источник на ветвь; вложенные запросы в `FROM` не поддерживаются |
| `ВНУТРЕННЕЕ` / `ЛЕВОЕ` / `ПРАВОЕ` / `ПОЛНОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ` | 🟡 | одно соединение на ветвь; в `ПО` требуется хотя бы одно равенство прямых полей разных источников, дополнительно допускаются скалярные фильтры через `И`; `ПОЛНОЕ` транспонируется в `UNION ALL`, агрегаты над ним запрещены |
| `ГДЕ` / `WHERE` | ✅ | |
| `СГРУППИРОВАТЬ ПО` / `GROUP BY`, `ИМЕЮЩИЕ` / `HAVING` | ❌ | ключевые слова распознаются лексером, парсер отклоняет; агрегаты допустимы только без неагрегатных полей |
| `СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ` / `GROUPING SETS` (8.3.16) | ❌ | |
| `ОБЪЕДИНИТЬ [ВСЕ]` / `UNION [ALL]` | ✅ | ветви должны совпадать по числу колонок и вариантам `ColumnKind` (`NULL` совместим с любым) |
| `УПОРЯДОЧИТЬ ПО … ВОЗР/УБЫВ` / `ORDER BY … ASC/DESC` | 🟡 | только в конце запроса, только по полям (без выражений и порядковых номеров); при `JOIN`/`UNION` поле должно быть в проекции |
| `АВТОУПОРЯДОЧИВАНИЕ` / `AUTOORDER` | ❌ | |
| `ИТОГИ … ПО` / `TOTALS … BY` (`ОБЩИЕ`, `ИЕРАРХИЯ`, `ПЕРИОДАМИ`) | ❌ | |
| `ДЛЯ ИЗМЕНЕНИЯ` / `FOR UPDATE` | ❌ | компилятор только для чтения |
| `ПУСТАЯ ТАБЛИЦА` / `EMPTYTABLE` | ❌ | |
| Вложенные запросы (в `ИЗ`, `ГДЕ`, `В (…)`, списке выбора) | ❌ | `UnsupportedFeature` |
| Пакет запросов `;` | 🟡 | завершающие `;` допустимы; несколько запросов в одном тексте не выполняются |
| Разыменование `Поле.Реквизит` | 🟡 | один шаг; глубже — «reference paths deeper than one hop are not supported»; в `ПО` разыменование запрещено |
| `.Представление` / `.Presentation` | ✅ | через callback-план приложения (см. README «Callback ABI представлений») |

## 2. Операторы

| Оператор | Статус | Примечание / реакция |
|---|---|---|
| `+ - * /` | ✅ | `%` — ❌ |
| `+` как конкатенация строк | ❌ | компилируется как арифметика (`Number`); на СУБД даст ошибку типов |
| `= <> < > <= >=` | ✅ | |
| `И` / `ИЛИ` / `НЕ` | ✅ | на MSSQL булевы поля в предикатах приводятся к `= 0x01` |
| `В (список)` / `IN (...)` | ✅ | непустой список скалярных выражений, в том числе `ЗНАЧЕНИЕ(...)` |
| `В (подзапрос)` | ❌ | |
| `В ИЕРАРХИИ` / `IN HIERARCHY` | ❌ | |
| `МЕЖДУ … И …` / `BETWEEN` | ❌ | не ключевое слово → `Syntax` |
| `ПОДОБНО … [СПЕЦСИМВОЛ]` / `LIKE … [ESCAPE]` | ❌ | |
| `ЕСТЬ NULL` / `ЕСТЬ НЕ NULL` | ✅ | |
| `ССЫЛКА Справочник.X` / `REFS` | ❌ | частично заменяется `ВЫРАЗИТЬ(… КАК Справочник.X) ЕСТЬ НЕ NULL` |
| `ВЫБОР КОГДА … ТОГДА … ИНАЧЕ … КОНЕЦ` / `CASE` | ❌ | ключевые слова в лексере есть, парсер отклоняет |

## 3. Функции

### Агрегатные

| Функция | Статус | Примечание |

| `АВТОНОМЕРЗАПИСИ` / `RECORDAUTONUMBER` | ❌ | |
| `РАЗМЕРХРАНИМЫХДАННЫХ` / `STOREDDATASIZE` (8.3.20) | ❌ | |

| Источник | Статус | Примечание |

| `Справочник`, `Документ`, `Перечисление`, `ПланВидовХарактеристик`, `ПланСчетов`, `ПланВидовРасчета`, `ПланОбмена`, `РегистрСведений`, `РегистрНакопления`, `РегистрБухгалтерии`, `РегистрРасчета`, `БизнесПроцесс`, `Задача`, `Константа`, `Последовательность` | ✅ | русские, английские и короткие имена видов (`Catalog`/`Reference`, `InfoRg`, `AccumRg`, …); объект должен иметь живую таблицу |

## 7. Что open-sdbl добавляет сверх языка 1С

- Бинарные литералы `0x…` и `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ поле)` в исходной форме.
- `ColumnKind` для каждой колонки результата и нативные типы вместо текста.
- Уровень диалекта MSSQL (`2008`/`2012`), поддержка PostgreSQL 9.0+ и баз
  платформы 8.2 без `PartNo`.
