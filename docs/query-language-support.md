# Язык запросов 1С: статус поддержки в open-sdbl

Сверка выполнена 2026-09-11 по версии 0.3.5. Перечень возможностей языка
запросов взят из раздела «Язык запросов» Синтакс-помощника платформы
8.3.27.2342. Статус — из кода `open-sdbl` (`src/lexer.rs`,
`src/query/core/parser.rs`, `src/query/core/codegen/`) и спецификаций
`openspec/specs/`.

Обозначения: ✅ поддерживается · 🟡 частично (см. примечание) · ❌ не
поддерживается. В графе «Примечание / реакция» — диагностика, которую
выдаёт компилятор (`QueryDiagnosticKind`), если конструкция встречается в
запросе.

Страницы Синтакс-помощника, по которым проверялись конструкции, названы во
вводных абзацах разделов; открыть страницу можно поиском по её названию.

Обзор проекта, примеры запросов и описание API — в [README](../README.md).

## 1. Структура запроса

Порядок предложений по странице «Секция ВЫБРАТЬ (Описание запроса)»:
`ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ n] <поля> [ПОМЕСТИТЬ …] [ИЗ …]
[ИНДЕКСИРОВАТЬ ПО …] [ГДЕ …] [СГРУППИРОВАТЬ ПО …] [ИМЕЮЩИЕ …]
[ДЛЯ ИЗМЕНЕНИЯ …]`, затем `ОБЪЕДИНИТЬ`, `УПОРЯДОЧИТЬ ПО`,
`АВТОУПОРЯДОЧИВАНИЕ`, `ИТОГИ`.

| Статус | Конструкция (RU / EN) | Примечание / реакция |
| --- | --- | --- |
| ✅ | `ВЫБРАТЬ` / `SELECT` |  |
| ✅ | `РАЗЛИЧНЫЕ` / `DISTINCT` |  |
| ✅ | `ПЕРВЫЕ n` / `TOP n` | `TOP (n)` на MSSQL, `LIMIT n` на PostgreSQL; `n` — целое > 0 |
| 🟡 | `РАЗРЕШЕННЫЕ` / `ALLOWED` | только после первого `ВЫБРАТЬ` оператора, действует на его вложенные запросы, `В (…)`, объединение и виртуальные таблицы; операторы пакета независимы; фильтры не читаются из ролей, а запрашиваются у приложения (`Prepared::restriction_request` → `CompileOptions::restrictions`) как условия на SDBL и оборачивают таблицу в производную `(SELECT … FROM t AS "__restricted" WHERE …)`, у виртуальных таблиц добавляются к их условию (только прямые поля); разыменованные таблицы не фильтруются; в консоли — `\restrict`; подробнее — README «Ограничения доступа» |
| ✅ | Псевдонимы `[КАК]` / `[AS]` | для полей и источников; `КАК` необязательно и в 1С |
| 🟡 | `*` | только без других полей и без `JOIN` |
| ✅ | Запрос без `ИЗ` | в 1С `ИЗ` можно опустить при полностью квалифицированных полях; open-sdbl без `ИЗ` компилирует только выражения без источника (`ВЫБРАТЬ 1`) |
| ❌ | Вложенные таблицы в выборке `Состав.(Поле, …)`, `Состав.*`, `ПУСТАЯТАБЛИЦА.(…)` / `EMPTYTABLE` | табличная часть доступна только как отдельный источник `Документ.X.Состав` |
| ✅ | `ПОМЕСТИТЬ <ВТ>` / `INTO`, `УНИЧТОЖИТЬ <ВТ>` / `DROP` | базы-копии только на чтение, поэтому таблица эмулируется CTE `vt1`, `vt2`, …: `ПОМЕСТИТЬ` определяет CTE и возвращает строку `Количество`, `УНИЧТОЖИТЬ` SQL не порождает и скрывает имя (можно определить заново); определения хранит `TempTablesManager`, в `WITH` попадают только достижимые; правила определения — как у вложенного запроса (`*`, отложенные представления и `УПОРЯДОЧИТЬ ПО` без `ПЕРВЫЕ` запрещены); неизвестное или дублирующее имя — `TemporaryTable` |
| ✅ | `ДОБАВИТЬ <ВТ>` / `ADD` (добавление строк в существующую ВТ) | новая CTE `SELECT … FROM vtK UNION ALL <оператор>`, имя переключается на неё; структура сверяется строго (число колонок, виды, цели и ширина ссылок), расширения типа нет; метки колонок остаются от первого определения; поле перед `ДОБАВИТЬ` не обязано иметь псевдоним, в отличие от 1С |
| 🟡 | `ИНДЕКСИРОВАТЬ ПО …` / `INDEX BY`, `ИНДЕКСИРОВАТЬ ПО НАБОРАМ ((…),(…))` / `INDEX BY SETS`, модификатор `УНИКАЛЬНО` / `UNIQUE` | разбирается и проверяется (поля обязаны быть в списке выборки, иначе `TemporaryTable`), SQL не порождает: у CTE индексов нет |
| ✅ | `ИЗ <ВТ> [КАК Псевдоним]` (чтение временной таблицы) | имя без точки читается как временная таблица, в том числе в соединениях, вложенных запросах и `В (…)`; без псевдонима квалификатором служит имя таблицы; колонки приходят с видами из определения; разыменование — как у вложенного источника |
| ❌ | `ИЗ &ВнешнийИсточник` (ВТ из таблицы значений) | внешние источники данных в компиляторе отсутствуют |
| ❌ | `ИЗ` / `FROM`: несколько источников через запятую | декартово произведение через запятую не поддерживается; используйте соединения |
| ✅ | `ИЗ (вложенный запрос) КАК Псевдоним`, в том числе в соединениях | псевдоним обязателен; колонки подзапроса становятся полями источника с их `ColumnKind`; внутри допустимы объединения, группировка, соединения, `ПЕРВЫЕ`, `РАЗЛИЧНЫЕ`, inline-представления, `УПОРЯДОЧИТЬ ПО` только вместе с `ПЕРВЫЕ`; запрещены `*` и отложенные представления; разыменование — только через колонку-ссылку с одной фиксированной целью; коррелированные ссылки на внешние источники — диагностика; глубина вложенности ≤ 16 |
| 🟡 | `[ВНУТРЕННЕЕ] СОЕДИНЕНИЕ`, `ЛЕВОЕ/ПРАВОЕ/ПОЛНОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ … ПО` / `[INNER] JOIN`, `LEFT/RIGHT/FULL [OUTER] JOIN … ON` | цепочка любого числа соединений в порядке записи; ссылки разной ширины в равенстве приводятся к `RTRef ‖ RRRef` (фиксированная получает номер типа цели, составная конкатенируется, payload остаётся как есть), две составные сравниваются почленно; `ПО` каждого соединения содержит хотя бы одно равенство прямых полей или одношаговых разыменований присоединяемого и любого более раннего источника, дополнительно — скалярные фильтры через `И`; при разыменовании в `ПО` соединения разыменования выводятся группой рядом со своим источником; ссылка на источник, присоединяемый позже, — диагностика; путь глубже одного шага и разыменование в `ПО` у `ПОЛНОЕ` — диагностика; `ПОЛНОЕ` допустимо только единственным соединением ветви, транспонируется в `UNION ALL`, агрегаты над ним запрещены |
| ✅ | `ГДЕ` / `WHERE` |  |
| ✅ | `СГРУППИРОВАТЬ ПО` / `GROUP BY`, `ИМЕЮЩИЕ` / `HAVING` | ключи — путь поля (одно разыменование), псевдоним проекции или выражение, совпадающее с проекцией; каждая неагрегатная проекция обязана быть ключом; ссылочный ключ группируется по всем физическим членам; `ИМЕЮЩИЕ` — предикат с агрегатами; сортировка сгруппированной ветви — только по ключам и псевдонимам; с `ПОЛНОЕ СОЕДИНЕНИЕ` — диагностика |
| ❌ | `СГРУППИРОВАТЬ [ВСЕ] ПО ГРУППИРУЮЩИМ НАБОРАМ ((…),(…))` / `GROUP BY GROUPING SETS` |  |
| ✅ | `ОБЪЕДИНИТЬ [ВСЕ]` / `UNION [ALL]` | ветви должны совпадать по числу колонок и вариантам `ColumnKind` (`NULL` совместим с любым); 1С в этом месте образует составной тип |
| 🟡 | `УПОРЯДОЧИТЬ ПО … ВОЗР/УБЫВ` / `ORDER BY … ASC/DESC` | только в конце запроса, только по полям (без выражений и порядковых номеров); при `JOIN`/`UNION` поле должно быть в проекции |
| ❌ | `УПОРЯДОЧИТЬ ПО … [ВОЗР/УБЫВ] ИЕРАРХИЯ` / `HIERARCHY` |  |
| ❌ | `АВТОУПОРЯДОЧИВАНИЕ` / `AUTOORDER` |  |
| ❌ | `ИТОГИ [поля] ПО [ОБЩИЕ] точки [[ТОЛЬКО] ИЕРАРХИЯ] [ПЕРИОДАМИ(…)]` / `TOTALS … BY [OVERALL] … [[ONLY] HIERARCHY] [PERIODS]` | итоговые строки — особенность результата запроса 1С, в SQL не отображаются |
| ❌ | `ДЛЯ ИЗМЕНЕНИЯ [OF таблицы]` / `FOR UPDATE [OF]` | компилятор только для чтения |
| ✅ | `[НЕ] В (вложенный запрос)` | подзапрос ровно с одной колонкой совместимого вида; ссылки сравниваются на одной ширине (fixed сторона расширяется до `RTRef ‖ RRRef`); подзапросы в списке выбора — ❌ (их нет и в 1С) |
| 🟡 | Пакет запросов `;` | операторы пакета компилируются последовательно (не более 64) и собираются в один SQL-оператор: результат даёт последний, как `Запрос.Выполнить()`; промежуточные запросы без `ПОМЕСТИТЬ` только проверяются; массива результатов, как у `ВыполнитьПакет()`, нет; пакет из одного `УНИЧТОЖИТЬ` строк не возвращает |
| 🟡 | Разыменование `Поле.Реквизит[.Реквизит…]` | один шаг; глубже — «reference paths deeper than one hop are not supported»; допустимо в проекции, `ГДЕ`, `СГРУППИРОВАТЬ ПО`, `УПОРЯДОЧИТЬ ПО` и `ПО` (кроме `ПОЛНОЕ`); имя таблицы можно опускать, если поле уникально среди источников |
| ✅ | Разыменование составного поля (`ЛюбаяСсылка`, `Регистратор`, payload подзапроса или ВТ) | цели берутся из SchemaStorage, из вида колонки подзапроса либо перебором ссылочных объектов с таким реквизитом; на каждую цель `LEFT JOIN` с охраной по типу, значение — `ВЫБОР` по `_RTRef`, для типов без реквизита `NULL`; виды реквизита должны совпадать по варианту, ссылки расширяются до `RTRef ‖ RRRef`; больше 32 целей, представление результата и второй шаг — диагностика |
| ✅ | `.Представление` / `.Presentation` | через callback-план приложения (см. README «Callback ABI представлений») |

## 2. Операторы

Грамматика логических выражений по страницам «Логические выражения в языке
запросов» и «Логические операторы»: сравнение `> < = >= <= <>`, `[НЕ] В [ИЕРАРХИИ]
(список | подзапрос)`, `[НЕ] МЕЖДУ … И …`, `ЕСТЬ [НЕ] NULL`, `ССЫЛКА <Имя
таблицы>`, `[НЕ] ПОДОБНО … [СПЕЦСИМВОЛ …]`, связки `И ИЛИ НЕ`.

| Статус | Оператор | Примечание / реакция |
| --- | --- | --- |
| ✅ | `+ - * /` | `%` — ❌ (в справке не описан) |
| ❌ | `+` как конкатенация строк | компилируется как арифметика (`Number`); на СУБД даст ошибку типов |
| ✅ | `= <> < > <= >=` |  |
| ✅ | `И` / `ИЛИ` / `НЕ` (`AND` / `OR` / `NOT`) | на MSSQL булевы поля в предикатах приводятся к `= 0x01` |
| ✅ | `В (список)` / `IN (...)` | непустой список скалярных выражений, в том числе `ЗНАЧЕНИЕ(...)` |
| ✅ | `НЕ В (список)` / `NOT IN` |  |
| ❌ | `[НЕ] В ИЕРАРХИИ (…)` / `IN HIERARCHY` |  |
| ❌ | `[НЕ] МЕЖДУ … И …` / `BETWEEN` | не ключевое слово → `Syntax` |
| ✅ | `[НЕ] ПОДОБНО … [СПЕЦСИМВОЛ …]` / `[NOT] LIKE … [ESCAPE …]` | шаблон передаётся в `LIKE` без переписывания на обоих провайдерах (на PostgreSQL классы `[…]` обеспечивает `mchar`); операнды — строки; только в предикатах |
| ✅ | `ЕСТЬ NULL` / `ЕСТЬ НЕ NULL` (`IS [NOT] NULL`) |  |
| ❌ | `ССЫЛКА Справочник.X` / `REFS` | частично заменяется `ВЫРАЗИТЬ(… КАК Справочник.X) ЕСТЬ НЕ NULL` |
| ✅ | `ВЫБОР КОГДА … ТОГДА … [ИНАЧЕ …] КОНЕЦ` / `CASE WHEN … THEN … [ELSE …] END` | вид результата — первая не-`NULL` ветвь, остальные должны быть совместимы; ссылки на разные объекты расширяются до runtime-typed payload; агрегаты внутри `ВЫБОР` допустимы в сгруппированных ветвях и в ветвях из одних агрегатов |

### Агрегатные

| Статус | Функция | Примечание |

### Типы и значения

| Статус | Функция | Примечание |
| --- | --- | --- |
| ✅ | `ВЫРАЗИТЬ(x КАК БУЛЕВО \| ЧИСЛО [(Длина[, Точность])] \| СТРОКА [(Длина)] \| ДАТА)` / `CAST … AS BOOLEAN \| NUMBER \| STRING \| DATE` | `ЧИСЛО` без параметров на MSSQL — `numeric(38, 10)`; в 1С длина `СТРОКА` ограничена 1024 |
| ✅ | `ВЫРАЗИТЬ(x КАК Справочник.X)[.Реквизит]` | значение — `RRRef` под guard `RTRef`, чужие типы → `NULL` (как в 1С); одно разыменование через `LEFT JOIN`; в `ПО` допустимо само сужение, но не `.Реквизит` после него («JOIN condition supports direct fields only») |
| ✅ | `ЗНАЧЕНИЕ(Перечисление.X.Y)`, `ЗНАЧЕНИЕ(Справочник.X.Предопределенный)` / `VALUE` | только справочники и перечисления |
| ✅ | `ЗНАЧЕНИЕ(<Вид>.<Объект>.ПустаяСсылка)` / `EmptyRef` | 16 нулевых байт с видом `Reference{targets: [объект]}` для всех ссылочных видов; сравнение с runtime-typed полем проверяет `_RTRef` и `_RRRef` |
| ❌ | Литерал `ТИП(Строка)`, `ТИП(Справочник.X)` / `TYPE` |  |
| ❌ | `ТИПЗНАЧЕНИЯ(x)` / `VALUETYPE` |  |
| ✅ | `ЕСТЬNULL(x, y)` / `ISNULL` | `COALESCE(x, y)`; вид — вид `x` (или `y`, если `x` — `NULL`); ссылки расширяются как в `ВЫБОР` |
| ✅ | `ПРЕДСТАВЛЕНИЕ(x)` / `PRESENTATION`, `ПРЕДСТАВЛЕНИЕССЫЛКИ(x)` / `REFPRESENTATION` | аргумент — поле или литерал; универсальные ссылки резолвятся отложенно пакетами |
| ✅ | `УНИКАЛЬНЫЙИДЕНТИФИКАТОР(x)` / `UUID` | нативный `uuid` / `uniqueidentifier`; аргумент — ссылочное поле; `NULL → NULL` как в 1С; нессылочный аргумент — ошибка компиляции (в 1С — ошибка выполнения) |
| ❌ | `АВТОНОМЕРЗАПИСИ()` / `RECORDAUTONUMBER` | в 1С допустима только в запросе с `ПОМЕСТИТЬ` |
| ❌ | `РАЗМЕРХРАНИМЫХДАННЫХ` | английское написание в справке не приведено |

## 5. Стандартные поля

В скобках — написание, которое принимает open-sdbl, если оно отличается от
имени 1С. Английские имена платформы `Ref`, `DeletionMark` и `LineNumber` не
распознаются: пишите `ID`, `Marked`, `LineNo` или русский синоним.

| Статус | Поле (RU / EN) | Примечание |
| --- | --- | --- |
| ✅ | `Ссылка` / `Ref` (`ID`), `Код` / `Code`, `Наименование` / `Description`, `ПометкаУдаления` / `DeletionMark` (`Marked`), `ВерсияДанных` / `Version`, `Номер` / `Number`, `Дата` / `Date`, `Проведен` / `Posted`, `Регистратор` / `Recorder`, `НомерСтроки` / `LineNumber` (`LineNo`), `Период` / `Period`, `Активность` / `Active` | у каждого из двенадцати полей принимаются оба синонима — русский и схемный |
| 🟡 | `Предопределенный` / `Predefined`, `ПредопределенноеИмя` / `PredefinedDataName`, `ЭтоГруппа` / `IsFolder`, `Родитель` / `Parent`, `Владелец` / `Owner`, `ВидДвижения` / `RecordType` | пишутся схемным именем из SchemaStorage (`Predefined`, `Folder`, `ParentID`, `OwnerID`, `RecordKind`), русские синонимы не заведены |

## 6. Литералы, параметры, комментарии

По странице «Константы и параметры в языке запросов» литералами являются
`ИСТИНА`, `ЛОЖЬ`, число, строка, `ДАТАВРЕМЯ(…)`, `ТИП(…)`, параметр `&Имя`,
`НЕОПРЕДЕЛЕНО`, `NULL`.

| Статус | Элемент | Примечание |
| --- | --- | --- |
| ✅ | Строки `"…"` с удвоением `""` | многострочные литералы с `\|` — ❌ |
| ✅ | Числа |  |
| ✅ | `ИСТИНА` / `ЛОЖЬ` / `NULL` (`TRUE` / `FALSE`) |  |
| ❌ | `НЕОПРЕДЕЛЕНО` / `UNDEFINED` |  |
| ❌ | `ТИП(…)` / `TYPE` | см. раздел 3 |
| ✅ | Бинарные литералы `0x…` | расширение open-sdbl (нет в 1С) |

| ✅ | Комментарии `//` |  |

## 7. Что open-sdbl добавляет сверх языка 1С

- Бинарные литералы `0x…`.
- Ключевое слово `ON` вместо `ПО` в условии соединения; короткие английские
  имена видов метаданных (`Reference`, `InfoRg`, `AccumRg`, …) и физические
  имена стандартных полей (`Folder`, `ParentID`, `RecordKind`, …).
- `ColumnKind` для каждой колонки результата и нативные типы вместо текста.
- Параметры сеанса: `SessionParameters` видны каждому запросу и каждому
  ограничению доступа, в отличие от параметров одного `Запрос`а.
- Прикладная политика вместо ролей конфигурации: представления значений
  (`PresentationPlan`) и построчные ограничения `РАЗРЕШЕННЫЕ`
  (`AccessRestriction`) приходят от приложения через callback, потому что
  ядро не выполняет ввод-вывод и не читает роли.
- Уровень диалекта MSSQL (`2008`/`2012`), поддержка PostgreSQL 9.0+ и баз
  платформы 8.2 без `PartNo`.
