# Собственные реквизиты каталогов buh: форма 56/61

Проверено нативной платформой 1С 8.3.27.2342 2026-10-02: выгрузка XML оригинальной buh выполнена только чтением. Объект `92876c9e-52ff-480d-9878-5766f4f9d12c` — справочник `ВнешниеПользователи`; одноимённый `e5dfee58-f748-48ee-81a3-7c6133f06365` — общий модуль. Имя не использовалось для определения вида.

Дескриптор справочника использует класс Config `56` с 61 значением. Прежняя проверка принимала только класс `57`, поэтому полная собственная коллекция оставалась неизвестной. Теперь измеренная форма `56/61` проходит существующие проверки префикса, GUID владельца, размера коллекции и уникальности элементов. Реквизиты и существующие настройки проецируются тем же кодом; неизвестные длины остаются неизвестными. Публичные сигнатуры, версия 0.9.6 и зависимости не изменены.

Все 84 справочника этой формы сверены с XML: 733 собственных UUID совпали по составу и порядку. У `ВнешниеПользователи` восемь собственных реквизитов; второй — `ОбъектАвторизации`, GUID `d65c4485-7bac-4206-9a6c-7156f4bb876d`. Сжатый текущий ресурс совпадает с прежним `tests/fixtures/buh/config.pack`. Oracle и отрицательная фикстура неизвестной длины находятся в `tests/fixtures/buh-catalog-layout-56`.

Ограничения: другие формы каталогов buh (`46`, `47`, `52`, `53`, `54`) в этом исправлении не включены. Непонятный `Pattern` реквизита сохраняет `declared_types=None`, даже когда его собственный UUID и имя известны; приобретение имени не доказывает поддержку всех типов. SQL-запись, выделение номеров и изменение оригинальной базы не выполнялись.
