# Проверка чтения значения константы в 0.9.5

Значение константы в DBNames имеет GUID самой константы. Отдельного реквизита метаданных и отдельного права `Read` на этот реквизит у него нет. Проверка, ожидавшая явный грант дочернего реквизита, ошибочно отклоняла чтение `ОсновнойЯзык` при запуске УНФ.

На платформе 1С 8.3.27.2342 создана одноразовая файловая база с Boolean-константой и справочником. Аутентифицированные пользователи с объектным `Read` успешно выполнили запрос константы и вызвали `Получить()` при обоих значениях `setForAttributesByDefault`. После явного запрета объектного `Read` оба способа чтения завершились отказом доступа. XML и исходные результаты находятся в `tests/fixtures/access/native-095`. Рабочие базы demo, buh и unf не изменялись.

Исправление касается только подтверждённого значения константы: владелец обязан иметь вид Constant, поле должно быть разрешено снимком и иметь тот же GUID. Все права ролей должны быть прочитаны; неподтверждённые поля и вложенные пути остаются закрытыми. Проверка объекта остаётся прежней: явный запрет в одной роли может быть компенсирован грантом другой роли. Существующие тесты не менялись.

На реальной PostgreSQL UNF выполнена read-only проверка: `BlockingDatabaseSession.metadata`, чтение пользователей и ролей, выбор `Администратор`, затем `check_user_field_access` для значения `ОсновнойЯзык`. Результат: `UNF ОсновнойЯзык: field Read granted for Администратор`. Загрузчик сообщил о трёх непрочитанных ресурсах `.7` (не UTF-8); это не ресурсы прав, и все роли пользователя прочитаны. Полный запуск BSL-модуля УНФ относится к проверкам потребителя. Живого SQL Server в этом контуре нет.

## Оставшиеся границы

Native `ПравоДоступа("Чтение", Реквизит)` отвергает это право как неприменимое. `View` — другое право; переименовывать его в `Read` нельзя. Контрольные запросы реквизита и кода прошли, но возвращали ноль строк. Консервативная проверка обычных и стандартных реквизитов пока сохранена; для её расширения требуется отдельное измеренное сопоставление.

Сведения о расширениях не додумывались: `safe_mode` остаётся `None`, scope — исходный числовой код, а `content_hash` — CAS SHA1, не платформенный `HashSum`. Синтакс-помощник установленной 8.3.27.2342 подтверждает, что SafeMode бывает Boolean или строкой с именем профиля (страница `platform-syntax-help:syntax-context:objects/catalog63/catalog2326/ConfigurationExtension/properties/SafeMode10769.html`). Для декодирования нужны дифференциальные записи `_ExtensionsInfo` из одноразовой SQL-базы вместе с native значениями SafeMode/Profile, Scope и HashSum. Файловая база этого SQL свидетельства не предоставляет.
